## 0.7.0 (2026-08-05)

### Tag Query Performance
- Rewrote `listTags` SQL to single-pass window function (`ROW_NUMBER() OVER PARTITION BY tag ORDER BY updated_at`) instead of per-tag subqueries
- Added `idx_media_updated_at` index for faster tag aggregation

### Thumbnail Generation
- Concurrency limiter (max 3 parallel ffmpeg processes) prevents thumbnail request storms from spawning dozens of ffmpeg instances
- Switched to async `fs/promises` in thumbnail handler (non-blocking stat/access)
- Better handling of missing source files (async access check before spawn)

### Tag Page Pagination
- Tag page now uses server-side pagination (`fetchMedia({ limit, offset })`) instead of loading all media client-side
- Removed client-side page cache in favor of server pagination

### Lazy Thumbnail Loading
- `MediaCard` and `TagCard` use IntersectionObserver to defer thumbnail requests until the card is within 200px of the viewport
- Reduces server load on large grids significantly

### Offline Tag Search
- IndexedDB queries now support `search` and `tag` filters, mirroring server-side filter logic
- Tags list cached optimistically via `getLastTags()` — shows stale data immediately while fetching fresh

## 0.10.0 (2026-09-01)

### Refresh Fix (#54)
- Fixed the library Refresh command scanning **every** folder in the library instead of only the root folders. Each `POST /media/scan` already recurses a whole subtree, so a single full-library refresh redundantly walked thousands of folders and never completed.
- Refresh now reports scanning progress as `Scanning <name> (1/N)...` and surfaces per-root scan failures so a single failed root no longer silently skips its subtree.

### Incremental / Fast Scanning (#55)
- **Tier 3 — subtree-scoped path diff:** load existing media paths for only the scanned subtree (range predicate on the path index) instead of the whole library, shrinking memory and Set build per scan. The `.ts` stale-record cleanup now iterates subtree rows only.
- **Tier 1 — removed the backfill tax:** replaced the per-file DB lookup for every file in the subtree with a single query for `NULL date_taken` candidates plus a stat per candidate.
- **Wildcard-safe scope:** subtree scope uses a range predicate (`path >= dirPrefix AND path < dirPrefix + \u{10FFFF}`) instead of a `LIKE`/`substr` prefix test, so folder names containing `_` or `%` can no longer pull sibling rows into scope, and queries stay index-usable (`SEARCH ... USING INDEX`).
- **Case-insensitive `.ts` cleanup preserved:** stale `.ts` records are cleaned up via a `COLLATE NOCASE` prefix range so misdetected rows with casing that differs from the scan path are still removed; genuine MPEG-TS files are kept.
- Added unit tests for the case-variant removal (gated to case-insensitive filesystems) and the genuine-MPEG-TS keep behaviour.

## 0.11.0 (2026-09-02)

### Resume after mobile sleep/wake (#46, #26)

Mobile browsers reload a suspended/background tab on wake (and installed PWAs often relaunch at their start_url), which wiped all in-memory React state — the app dropped back to the dashboard and a shuffle session silently reverted to folder slide mode.

- **Slideshow session persistence:** the active slideshow (order, sequence, current index, history, total and its fetch source) is snapshotted to `sessionStorage` and restored on mount, so a shuffle session survives a reload. The sequence is stored under its own key and only re-serialised when it changes; the small position snapshot is written on every transition.
- **Pagination continuation:** `loadMore` is rebuilt from the persisted fetch source after a reload (FolderPage/Dashboard shuffle now pass that source).
- **Viewer state:** MediaPage uses `slideshow.currentIndex` while a slideshow is active so the counter/navigation is correct immediately after a restore.
- **Last-view resume:** a new `sessionNav` helper plus an index-route redirect restore the last non-landing view when a reload lands on `/` or `/dashboard`, so the app resumes where the user left off instead of resetting to the dashboard. Landing routes are not persisted, so a user who explicitly navigated to the dashboard stays there.

## 0.12.0 (2026-09-04)

### Duplicates Section (#57, #58)

New `/duplicates` page groups media sharing the same content hash, with tools to remove duplicates from the library.

- **Full-file content hash:** scanning now hashes the entire file (was the first 64KB + size) using an idle-timeout so large files aren't dropped during long reads. A matching hash now means exact byte-for-byte identity.
- **Verified groups:** `listDuplicates` re-verifies the file bytes for fingerprint candidates before returning group ids (a content hash is no longer exposed to the client). `merge`/`delete` take group ids, re-verify the group still exists byte-for-byte, and return 400 on a stale or singleton selection.
- **Merge tools:** merge a duplicate group into a single retained master record, migrating folder thumbnail references so a folder's chosen thumbnail isn't cleared. Group-level merge-all makes the intent explicit.
- **Delete tools:** delete every record in a duplicate group (or via the confirmation modal).
- **Cache sync:** the client clears its in-memory and IndexedDB folder caches after a merge/delete so counts and thumbnails stay consistent.
- **Liked navigation:** liked media now navigates through the liked list rather than the folder siblings.
- The duplicate verifier was moved out of the ops directory so kojo doesn't register it as a stateless op.
